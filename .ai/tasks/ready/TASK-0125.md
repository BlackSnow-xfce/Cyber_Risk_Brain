## Existing Incident Response Architecture

- `IncidentResponseWorkspace.tsx` is URL-authoritative and renders the overview,
  canonical queue, incident-specific Command Center or registered area page
  inside `IncidentResponseLayout.tsx`.
- `GET /api/incidents` through `getIncidents()` returns the persisted canonical
  queue projection with ID, lifecycle status, source, title, timestamps, owner
  and relationship counts.
- Canonical lifecycle values are `open`, `investigating`, `resolved`, `closed`.
  For this read-only overview only `open` and `investigating` are active. No
  other string or heuristic may be treated as active.
- `GET /api/incidents/{incidentId}/command-center` is an incident-scoped detail
  boundary with references, notes and activities. It is not an overview
  aggregation and must not be prefetched across incidents.
- `IncidentQueuePage.tsx` owns the existing complete queue search, loading,
  error, empty and Command Center navigation. It remains byte-identical.
