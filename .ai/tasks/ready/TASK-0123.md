## REWORK 1 - Active Execution Authority

The preceding dashboard implementation and its Architect Implementation Review

or authorize changes to the Threat Hunter dashboard implementation.

### Confirmed Root Cause

`WorkspaceSwitcher.tsx` owns a local `open` boolean and conditionally renders a
plain menu span. It closes only when the trigger is toggled or a workspace item
is selected. There is no Popover/Menu dismiss boundary, click-away handling,
Escape handling or related listener lifecycle, so a pointer interaction outside
the switcher cannot close the open menu.

### Exact Allowed Scope

- `frontend/src/components/topbar/WorkspaceSwitcher.tsx` - add the smallest
  component-local outside-interaction and Escape dismiss lifecycle while
  preserving the existing workspace selection and routing boundary.
- `frontend/src/components/topbar/WorkspaceSwitcher.test.tsx` - prove trigger,
  outside, inside, selection, Escape, listener and cleanup behavior.

No wildcard, implicit file or additional authority is granted. No CSS, Topbar,
dashboard, Registry, routing, workspace, backend, provider, runtime or
environment file may change.

### REWORK 1 Acceptance Criteria

- Clicking the closed WorkspaceSwitcher trigger opens the menu and clicking the
  same trigger again closes it.
- Selecting any enabled workspace calls the existing `setWorkspace()` boundary,
  navigates through the existing canonical `workspaceRoutes` mapping and closes
  the menu after the menu action is processed.
- A pointer interaction outside both the trigger and menu closes the menu
  immediately without preventing or consuming the outside target's own action.
- Pointer interactions inside the trigger/menu boundary are not treated as
  click-away and menu-item actions complete before dismissal.
- Escape closes an open menu without changing workspace or route. Escape and
  outside listeners are active only while needed and are removed on close and
  component unmount; repeated open/close cycles do not accumulate listeners.
- Existing grouping, labels, current identity, purple selected state, checkmark,
  `aria-current`, `WorkspaceId`, routes, Back/Forward and URL authority remain
  unchanged.
- The TASK-0123 dashboard, truthful Active Hunts state and canonical persisted
  Hunt Hypotheses behavior remain byte-identical.
- No global document-click workaround may block propagation or default behavior.
  A component-local boundary and standard React DOM event lifecycle are used;
  no CSS or global shell change is authorized.
- Scope Guard reports exactly the two authorized files. No fake data, backend or
  provider behavior is introduced.
