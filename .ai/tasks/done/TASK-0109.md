The current productive Finding Explanation path is:

```text
POST /api/findings/{finding_id}/explanation
  → FindingExplanationUseCase
  → Authorization
  → Trusted Retrieval
  → BoundAIContext
  → Context Admission
  → Asset/Risk readiness
  → Model-Egress projection
  → fixed instructions + structured schema
  → OpenAIFindingExplanationModel
  → OpenAI Responses API
  → schema validation
  → Disclosure Policy
  → Output Security Guard
  → FindingExplanationResult
  → API/UI
```

Provider selection is currently fixed by application wiring and the model ID
is supplied through `OPENAI_FINDING_EXPLANATION_MODEL`. There is no canonical
typed, purpose-bound selection decision, explicit model-version identity or
selection-policy reference.

## Objective

Introduce the smallest canonical governance boundary that makes model
selection for the existing Finding Explanation purpose explicit, typed,
deterministic, policy-controlled, fail-closed and traceable.

TASK-0109 does not implement a general model platform. It governs only the
existing Finding Explanation execution target.

## 1. Canonical AI Purpose

Reuse the existing `AIModelEgressPurpose` rather than creating a parallel
purpose enum. The only supported purpose in this task is:

`FINDING_EXPLANATION`

The purpose is application-selected and immutable. The LLM must not select,
modify or expand it. No generic workflow-, agent- or tool-purpose framework is
part of this task.

## 2. Model Execution Identity

Introduce the smallest immutable typed identity required to distinguish an
approved execution target. It must contain at least:

- `provider_id`
- `model_id`
- `execution_binding_version`

`execution_binding_version` is an explicit PredatorAI-local governance binding
revision. It is not an OpenAI provider model version and must not be inferred
from model output or silently copied from a free-form model name.

## 3. Model Selection Policy

Introduce a deterministic positive allowlist for combinations of:

```text
AI Purpose + Provider + Model + Version
```

The initial allowlist contains only the currently supported Finding Explanation
OpenAI execution target. The concrete model-version value must be declared
explicitly by the implementation and tests; it must not be derived from the
model identifier.

Unknown, missing or unapproved provider/model/version combinations, purposes
or policy references fail closed. The LLM never participates in selection.

The policy owns the allowlist. Environment configuration may provide the
runtime target only when it resolves to an explicitly approved policy entry;
configuration must not create an implicit new approval.

## 4. Selection Decision

Produce an immutable typed selection decision containing exactly the approved
identity and at least:

- purpose
- provider_id
- model_id
- execution_binding_version
- selection_policy_reference

The decision represents PredatorAI's approved execution target, not a claim
made by the model or provider response.

## 5. Finding Explanation Integration

Resolve the selection decision before invoking the existing
`OpenAIFindingExplanationModel`. The adapter may remain the only actual
provider adapter.

The adapter must consume the approved decision and reject runtime identity
mismatches. Runtime provider/model/version identity must not silently diverge
from the approved governance identity.

Do not implement dynamic provider switching, provider migration, fallback or
LLM-controlled selection.

Existing Authorization Scope, Trusted Retrieval, BoundAIContext, Context
Admission, Classification, Model Egress, Disclosure Policy and Output Security
Guard remain unchanged and are executed in their existing order.

## 6. Traceability

The approved selection identity and policy reference must remain available in
the existing Finding Explanation result/execution context. It must be possible
to determine:

- which purpose was executed;
- which provider was approved;
- which model was approved;
- which model version was approved;
- which selection policy authorized the combination.

No persistent audit subsystem is required. A later task may convert the
decision into durable governance or audit events.

## 7. Architectural Invariants

1. Model selection is a trusted application/domain decision, never an LLM
   decision.
2. Provider/model selection cannot expand authorization, retrieval, admission,
   egress or output privileges.
3. Unknown or unapproved combinations fail closed.
4. Runtime model identity and governance identity cannot silently diverge.
5. A selection decision is not Evidence, Authorization, Confirmation or
   Security Authority.
6. Model version/provenance describes execution identity; it does not establish
   model trustworthiness.

## 8. Explicit Non-Goals

TASK-0109 does not include:

- a full Model Registry or Provider Registry product;
- dynamic multi-provider routing or provider migration;
- an AI/LLM Gateway;
- general RAG or new retrieval;
- Agent/Tool execution;
- prompt registry or prompt lifecycle governance;
- persistent governance database or AI-call audit service;
- benchmarking, automatic model evaluation, fallback, cost/performance routing;
- UI/dashboard work;
- complete AIBOM;
- consolidation/removal of legacy `llm/` abstractions;
- any new trust boundary;
- changes to TASK-0108 or HuntHypothesis semantics.

## 9. Required Tests

Focused tests must cover:

1. approved Finding Explanation selection succeeds;
2. unknown provider is denied;
3. unknown model is denied;
4. unknown/unapproved model version is denied;
5. wrong AI purpose is denied;
6. the decision contains the exact approved purpose, provider ID, model ID,
   model version and selection-policy reference;
7. model execution consumes the governed decision rather than independently
   choosing an arbitrary identity;
8. runtime provider/model/version mismatch fails closed;
9. existing Finding Explanation security-boundary tests remain green;
10. model output cannot alter the approved selection decision.

## Architect Rework #1 Evidence

The authority inversion was corrected. `AIModelSelectionPolicy.resolve()` now
accepts only the governed AI purpose and constructs the complete approved
identity itself. The OpenAI adapter no longer supplies provider, model or
version values to the policy.

`OpenAIFindingExplanationModel` consumes the resulting decision, checks its
configured runtime model only for compatibility, and uses
`selection.model_id` in the OpenAI request. A missing decision or runtime model
mismatch fails before network invocation.

The misleading provider `model_version` field was removed. The decision and
API traceability now expose `execution_binding_version`, explicitly defined as
the PredatorAI-local governance binding revision. No provider model version is
claimed or read from the OpenAI response. Provider/model response fields remain
local adapter execution observations and are not presented as independently
verified provider metadata.
