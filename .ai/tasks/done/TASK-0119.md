# TASK-0119 - Governed Model Selection UI

**Status:** DONE / PASS / APPROVED
**Reviewer:** Architect
**Architect Review:** PASS / APPROVED
**Product Owner Live Acceptance:** PASS
**Track:** POST-MVP AI Governance

## Objective

Allow an authenticated and explicitly authorized Local Operator to select an
executable, server-registered model independently for each governed capability,
with server-side persistence and secret-free audit history.

## Required Governance

- The UI submits only exact provider/model identities returned by the server;
  no free-text identity input exists.
- Selection requires `ai_model_selection:update`, valid browser session, exact
  configured Origin and session-bound CSRF token.
- Registry membership, enabled state, capability authorization, adapter binding
  and current execution availability are all mandatory and fail closed.
- Selection persists server-side per capability and survives browser reload.
- Successful and rejected changes append safe audit records without credentials,
  prompts, responses or sensitive content.
- Finding Explanation consumes the persisted governed selection through the
  existing TASK-0117 selection decision, with no parallel fallback path.

## Non-Goals

No provider execution during selection, provider activation, credential
management, free-form model names, automatic fallback, new live adapters,
AI-generated hypotheses, model comparison, benchmarking or TASK-0120.

## Implemented Architecture

- `AIModelSelectionService` validates exact registry identity, enabled state,
  capability authorization, adapter binding and current execution availability.
- Mutation requires the existing verified Local Operator browser session,
  Origin/CSRF checks and exact `ai_model_selection:update` authority.
- `FileAIModelSelectionStore` persists one canonical selection per capability as
  strict UTF-8 JSON under the Git-ignored server runtime path using atomic replace.
- Successful and rejected decisions append secret-free JSONL audit events.
- `PersistedAIModelSelectionPolicy` makes the persisted Finding Explanation
  selection authoritative through the existing TASK-0117 decision contract.
- The Administrator page renders capability-specific dropdowns containing only
  registered identities. Unavailable entries are disabled with explicit reasons.
