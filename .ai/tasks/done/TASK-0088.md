# TASK-0088 – Enforce Finding Model Egress on Live Explanation Boundary

Status: DONE
Review: PASS / APPROVED
Reviewer: Architect

## Ist-Pfad

The live path is `FindingExplanationUseCase` →
`FindingExplanationInputBuilder` → `FindingExplanationService` →
`OpenAIFindingExplanationModel`. The use case reads the configured Findings
source and builds the existing explanation input before the provider adapter
is called.

## Implementation

The existing path now constructs `FindingModelEgressPayload` through the
canonical `FINDING_EXPLANATION_EGRESS_POLICY` and
`FindingModelEgressProjector` during input construction. The provider request
uses only `explanation_input.model_egress_data()`, containing the positively
projected `finding.title` and `finding.vendor_severity` fields.

The existing explanation/result contracts remain available for factual
context and audit semantics, but the model-bound request no longer uses the
complete `FindingExplanationInput.model_data()` representation.

DENY, purpose/resource mismatch, unsupported fields or projection failure
raise a controlled fail-closed error before `FindingExplanationService` can
invoke the provider. No retrieval, trust, authorization or admission state is
changed.
