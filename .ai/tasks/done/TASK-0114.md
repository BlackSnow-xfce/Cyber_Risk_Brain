# TASK-0114 - Hunt Hypothesis Reference Resolution Foundation

**Product Owner Live Acceptance:** PASS
**Reference Resolution Live E2E:** PASS
**Track:** POST-MVP Threat Hunter

## Objective

Add a read-only, on-demand reference-resolution path for persisted canonical
`HuntHypothesis 1.0` pointers without mutating the hypothesis or repository.

## Resolution Contract

Approved reference types:

- `finding`: exact canonical Finding ID through the configured Findings source;
- `asset`: exact canonical Asset ID through `AssetContextQueryService`;
- `cve`: canonical CVE through `ThreatIntelligenceQueryService`.

All other canonical types (`service`, `threat_intelligence`, `technique`,
`tactic`) remain explicitly unsupported.

Exact statuses:

- `resolved`
- `not_found`
- `source_unavailable`
- `unsupported`

Resolution confirms pointer identity only. It does not establish evidence,
compromise, hypothesis truth, support, rejection or lifecycle authority.

## Acceptance Criteria

- Resolution is invoked only on demand for one exact persisted hypothesis.
- `GET /api/hunt-hypotheses` remains unchanged and does not resolve references.
- Original pointer type and ID remain present in every transient result.
- Supported references use only existing authoritative application readers.
- Exact missing identities return `not_found` only when the source is usable.
- Configuration, source and timeout failures return `source_unavailable` per
  reference and are never represented as `not_found`.
- Unsupported canonical types remain visible with `unsupported` status.
- Duplicate, ambiguous, malformed or inconsistent authoritative data fails the
  complete request without leaking internal exception details.
- Resolution metadata is not persisted.
- The UI preserves canonical pointers and displays resolution status/context
  separately after explicit user action.
- Existing Hypotheses states, navigation and Hunts behavior remain unchanged.

## Implementation Evidence

`HuntHypothesisReferenceResolutionService` loads the selected hypothesis
through the existing query service and produces an immutable transient
projection. Finding, Asset and CVE readers are reused directly. The endpoint
`GET /api/hunt-hypotheses/{hypothesis_id}/reference-resolution` returns typed
resolution data, 404 for an unknown hypothesis and a generic 500 response for
integrity failures.

The Hypotheses UI adds one per-hypothesis `Resolve references` action. No
resolution request is sent during collection loading. The original pointers
remain visible, and result wording explicitly limits resolution to identity
context.
