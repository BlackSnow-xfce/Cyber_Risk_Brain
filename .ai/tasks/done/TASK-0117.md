# TASK-0117 - Multi-Model Governance and Provider Registry Foundation

**Status:** DONE / PASS / APPROVED
**Reviewer:** Architect
**Architect Review:** PASS / APPROVED
**Product Owner Live Acceptance:** PASS
**Track:** POST-MVP AI Governance

## Objective

Generalize the existing TASK-0109 model-selection allowlist into an immutable,
provider-neutral and capability-scoped registry for `openai`, `anthropic`,
`google` and `local_openai_compatible`, while preserving the accepted OpenAI
Finding Explanation execution semantics.

## Required Governance

- Canonical registrations explicitly bind provider, model, protocol family,
  deployment class, governance policy, capabilities and enabled/disabled status.
- Initial capabilities are `finding_explanation` and
  `hunt_hypothesis_proposal`; authorization never crosses capabilities.
- Selection is default-deny for unknown, disabled, mismatched or ambiguous
  identities and never performs fallback.
- Immutable decisions carry exact identity, capability, policy, trusted UTC
  decision time and deterministic reason.
- Provider adapters receive only a governed decision; provider SDK objects,
  credentials and raw configuration remain outside canonical contracts.
- Safe audit projections contain decision metadata only, never prompts,
  sensitive context, credentials or provider responses.

## Compatibility

TASK-0109's exact OpenAI `gpt-5.6` Finding Explanation identity, execution
binding `1.0`, policy reference and output semantics remain compatible. No
Anthropic, Google, local-model or Hunt Hypothesis generation execution is
introduced.

## Non-Goals

No model UI, automatic fallback, comparison, benchmarking, credential UI,
browser-to-provider calls, new live provider calls, TASK-0116 changes or
TASK-0118.

## Implemented Architecture

- `AIModelRegistry` owns an immutable tuple of unique, canonical registrations.
- `AIModelExecutionIdentity` binds a typed provider family, exact model,
  provider-compatible protocol family, deployment class and execution binding.
- `AIModelRegistration` adds an explicit governance policy, non-empty frozen
  capability set and enabled/disabled status.
- Selection requires exact capability, provider and model and returns an
  immutable version 2.0 decision with trusted UTC timestamp and deterministic
  reason. Unknown, disabled, mismatched and unauthorized identities fail closed.
- `AIModelSelectionAuditProjection` exposes only safe selection metadata.
- `GovernedAIProviderAdapter` is a generic provider-neutral execution protocol;
  the OpenAI Finding Explanation adapter implements it without exposing its SDK,
  credential or raw configuration.

## TASK-0109 Compatibility

`AIModelSelectionPolicy` remains the Finding Explanation compatibility facade.
Its default registry selects exactly OpenAI `gpt-5.6`, execution binding `1.0`
and the existing `policy:ai-model-selection:finding-explanation:1.0` reference.
The accepted `generate` adapter entry point remains available and delegates to
the governed provider-neutral execution boundary. Output semantics are unchanged.
