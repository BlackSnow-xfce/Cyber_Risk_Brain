## Existing architecture

The guard is isolated after the policy stage and before any future protected
disclosure boundary. It reuses `AIModelEgressPurpose` and
`AIContextClassification` and is not integrated into the current
Finding-Explanation service, API, frontend or OpenAI adapter.

## Implementation

`FindingExplanationOutputSecurityGuard` returns the immutable
`AIOutputSecurityResult` with typed PASS/DENY and reason codes. It supports
only `FINDING_EXPLANATION + INTERNAL` and performs no provider or LLM calls.

The deliberately small high-confidence detection scope is:

- PEM-style private-key markers;
- concrete `password`, `passwd`, `secret`, `api_key`, `client_secret` and
  `access_token` assignments.

Security terminology and placeholder assignments remain allowed. Detection
fails closed without redaction, and reasons never contain detected secret
values.
