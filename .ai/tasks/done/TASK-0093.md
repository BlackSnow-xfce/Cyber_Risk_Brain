## Existing path

The live path is `FindingExplanationUseCase` → `FindingExplanationInputBuilder`
→ `FindingExplanationService` → `OpenAIFindingExplanationModel` → the
Finding-Explanation API and `FindingExplanationSection` in the SOC frontend.
TASK-0088 already ensures that the provider receives only the positive
allowlist projection (`finding.title` and `finding.vendor_severity`).

## Implementation

`FindingExplanationService` now evaluates the existing
`AIOutputDisclosurePolicy` after the single provider call and before parsing or
returning a `FindingExplanationResult`. Only an ALLOW decision proceeds to the
existing `FindingExplanationOutputSecurityGuard`; only a PASS proceeds to the
existing structured-output validation and generated result. Security failures
return the existing additive failure shape with the dedicated
`OUTPUT_SECURITY_DENIED` status and never include raw model output or detected
secret values.

The policy and guard remain independent, provider-neutral, and do not elevate
model-output trust or grant authorization. No retry, second provider call,
redaction, API, UI, or persistence change is introduced.
