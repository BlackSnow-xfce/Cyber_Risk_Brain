## Ziel

Die fachlichen Aggregate des kanonischen Domänenmodells identifizieren und ihre Konsistenzgrenzen technologieunabhängig definieren.

Aggregate legen fest, welche bereits dokumentierten Canonical Entities innerhalb genau einer fachlichen Konsistenzgrenze gemeinsam verantwortet werden. Dieser Task dokumentiert ausschließlich diese Grenzen und führt keine Implementierung oder technische Struktur ein.

## Scope

Genau ein technologieunabhängiges Architekturartefakt `.ai/architecture/AGGREGATE-BOUNDARIES.md` erstellen.

Für jedes identifizierte Aggregate dokumentieren:

* eindeutiger Name
* Zugehörigkeit zu genau einer bestehenden kanonischen Domäne
* genau eine Aggregate Root aus den vorhandenen Canonical Entities
* fachlicher Zweck
* fachliche Begründung der Konsistenzgrenze
* enthaltene Canonical Entities
* verwendete Canonical Value Objects

Canonical Entities, die keinem Aggregate zugeordnet werden, sind zur Vollständigkeit ausdrücklich als nicht zugeordnet zu dokumentieren, ohne dafür eine neue Grenze zu erfinden.

## Architekturregeln

* Die bestehenden Domain Boundaries, Ownership-Verantwortungen, Canonical Entities und Canonical Value Objects bleiben unverändert.
* Jedes Aggregate gehört genau einer kanonischen Domäne.
* Jedes Aggregate besitzt genau eine Aggregate Root.
* Eine Aggregate Root muss eine bereits dokumentierte Canonical Entity sein.
* Jede Canonical Entity darf höchstens einem Aggregate angehören.
* Ein Aggregate darf keine Entity aus einer anderen Domäne enthalten.
* Verwendete Value Objects müssen aus dem bestehenden Katalog stammen und fachlich zur Owner-Domäne des Aggregates gehören.
* Ein Canonical Value Object darf von mehreren Aggregaten verwendet werden; seine fachliche Owner-Domäne und Bedeutung bleiben dabei unverändert.
* Value Objects werden durch ihre Verwendung nicht zu Entities oder Aggregate Roots.
* Konsistenz wird ausschließlich fachlich begründet; Transaktionen, technische Grenzen und Persistenz werden nicht festgelegt.
* Beziehungen und Koordination zwischen Aggregaten werden nicht modelliert.
* `DecisionResult` bleibt gemäß ADR-0001 das kanonische fachliche Ergebnis einer abgeschlossenen Decision.
* Die Beschreibung bleibt technologie-, workspace-, rollen- und implementierungsunabhängig.
