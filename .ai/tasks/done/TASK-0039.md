## Scope

Genau ein technologieunabhängiges Architekturartefakt `.ai/architecture/DOMAIN-EVENTS.md` erstellen.

Für jedes fachlich erforderliche Domain Event mindestens dokumentieren:

* eindeutiger Name in fachlicher Vergangenheitsform
* genau eine produzierende Domain
* genau ein auslösendes bestehendes Aggregate
* fachliche Bedeutung des bereits eingetretenen Ereignisses
* betroffene bestehende Aggregate
* zulässige fachliche Konsumenten
* fachliche Konsistenzregeln
* fachliche Reihenfolge oder Kausalität, sofern relevant

Zusätzlich eindeutig festhalten:

* welche Aggregate-Änderung das Event fachlich bestätigt
* welche fachliche Ownership beim Produzenten verbleibt
* welche Konsumenten das Event ausdrücklich nicht verwenden dürfen
* ob keine besondere Reihenfolge oder Kausalität über das auslösende Aggregate hinaus erforderlich ist
* dass ein Event keine Zustandsänderung an einer fremden Domain anordnet und kein technischer Transportvertrag ist

Nur fachlich notwendige Events aufnehmen, die aus bestehenden Domains, Aggregates, Relationships, Dependencies, Services und freigegebenen Policies ableitbar sind. Keine Events zur künstlichen Vollständigkeit erfinden. Domains oder Aggregates ohne nachweisbar erforderliches Domain Event ausdrücklich mit fachlicher Begründung dokumentieren.

## Architekturregeln

* Jedes Event besitzt genau eine produzierende Domain und genau ein auslösendes Aggregate dieser Domain.
* Produzierende Domain und Aggregate müssen unverändert in den bestehenden Architekturartefakten definiert sein.
* Ein Event beschreibt ausschließlich eine bereits eingetretene fachliche Tatsache.
* Ein Event ersetzt weder Aggregate-Ownership noch Aggregate-Invarianten, Domain Services oder Domain Policies.
* Betroffene Aggregate bleiben in ihren eigenen Konsistenzgrenzen.
* Zulässige Cross-Domain-Konsumenten müssen mit `AGGREGATE-RELATIONSHIPS.md`, `DOMAIN-DEPENDENCIES.md` und ADR-0007 vereinbar sein.
* Ein Konsument darf die fachliche Aussage des Produzenten weder verändern noch als eigene Wahrheit duplizieren.
* Kausalität wird nur dokumentiert, wenn sie aus bestehenden fachlichen Lebensläufen oder Beziehungen ableitbar ist.
* Der Katalog definiert keine Zustellung, technische Reihenfolge, Transaktion oder Verarbeitungszusage.
* DecisionResult, Decision Evidence, Explainability und Execution Trace bleiben gemäß ADR-0001 bis ADR-0007 getrennt.
* Bestehende Architekturartefakte und ADRs bleiben unverändert.
* Die Beschreibung bleibt technologie-, workspace-, rollen- und implementierungsunabhängig.
