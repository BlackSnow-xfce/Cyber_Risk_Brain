## Objective

Turn the existing Threat Intelligence Workspace into a coherent operational
analyst workspace using only real PredatorAI data. The workspace must make
available intelligence, vulnerability context, source/completeness state and
Finding-scoped drill-downs easy to inspect without inventing security facts.

## Scope

### Overview

Connect the existing Overview to supported real state only. Permitted
summaries include findings with CVE references, TI availability/completeness,
KEV/EPSS/CVSS availability and currently resolvable vulnerability
intelligence. Do not add an analytics backend or invent aggregate metrics.

### CVE Explorer

Preserve and operationalize the exact-CVE lookup through the existing
vulnerability endpoint. Display CVE identity, NVD/CVSS/EPSS/CISA KEV data,
exploitation evidence, provenance/source references and completeness or
unavailable states. Frontend types remain projections; no duplicate domain
model is allowed.

### Our Environment

Use real Findings data. Where a Finding has CVE/TI relationships, navigate to
the existing Finding-specific workflow. Do not fabricate asset/TI,
attacker, campaign, malware, exploitation or compromise relationships.

### Finding-scoped TI navigation

Preserve canonical context through:

`/findings?findingId=<finding_id>&focus=threat-intelligence`

The Finding identity and Threat Intelligence focus must survive navigation and
direct/deep-link loading.

### Workspace and URL behavior

Preserve WorkspaceSwitcher registration, Overview, Explorer and Environment
routes, browser Back/Forward and direct deep links. URL state remains
authoritative for registered workspace areas. Do not introduce a second
routing or navigation state machine.

### Presentation

Retain the established PredatorAI dark operational visual language without
redesigning the application shell or modifying the accepted SOC Analyst
Dashboard except for a strictly necessary shared navigation correction.

## Data and Semantic Guardrails

The UI must distinguish supported states such as `available`, `unavailable`,
`incomplete`, `not evaluated` and `not connected` wherever the contracts
provide them. Missing KEV is not proof of non-exploitation; missing EPSS is
not zero probability; unavailable TI is not absence of threat.

Threat Intelligence remains contextual information. It is not automatically
Evidence, Verification, Confirmation or an Incident conclusion.

## Explicit Non-Goals

TASK-0110 does not include:

- new Threat Intelligence domain architecture or a new feed platform;
- bulk feed ingestion, STIX/TAXII, attacker attribution or campaign tracking;
- malware relationship graphs or asset-centric TI correlation engines;
- persisted TI snapshots;
- artificial attack chains or unsupported exploitation claims;
- automatic Incident creation;
- new AI explanation or AI Governance work;
- AIBOM, eBPF/XDP, Compliance Graph or Governed Remediation;
- large RAG systems or autonomous agents;
- new persistence or backend architecture unless an existing API is proven
  insufficient for a strictly scoped acceptance requirement.
