## Implementation

Implemented the first narrow trusted retrieval boundary for the existing
Finding resource: `FindingTrustedRetrievalService`.

The service uses the existing `FindingsQueryService`-compatible reader and
performs all authorization checks before lookup. It confirms the exact
returned Finding ID, maps the Finding to an `AIContextItem 1.0`, and constructs
`BoundAIContext 1.0` under boundary control. It does not invoke admission.

### Mapping

- Resource type: `FINDING`
- Operation: `retrieve_finding`
- Context type: `SECURITY_FINDING`
- Trust: `UNTRUSTED`
- Provenance: `EXTERNAL`, source reference `finding:{source}:{id}`
- Classification: conservative deterministic `INTERNAL`; no Finding
  classification field exists and `PUBLIC` is never inferred.
- Content: Finding title only, avoiding a broad prompt payload.

### Fail-closed behavior

DENY, wrong operation, wrong resource type, scope mismatch, classification
mismatch, invalid identity, missing resource and returned identity mismatch
produce no `BoundAIContext`. Denied cases do not call the repository reader.
