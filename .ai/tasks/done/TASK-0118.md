# TASK-0118 - Multi-Model Governance Visibility

**Status:** DONE / PASS / APPROVED

**Architect Review:** PASS / APPROVED
**Product Owner Live Acceptance:** PASS
**Track:** POST-MVP AI Governance

## Objective

Expose the actual TASK-0117 model-governance registry and supported provider
families through a read-only backend projection and the visible Administrator
`AI Models` area without duplicating configuration or invoking a provider.

## Acceptance Criteria

- A read-only API projects all supported provider families and both governed
  capabilities from the canonical registry/contracts.
- Registered identity, capability authorization, enabled status, policy,
  execution binding, adapter availability and governance status remain
  semantically distinct.
- Providers without registrations or adapters are visibly identified as
  governance foundation only, never as configured or executable.
- The existing OpenAI Finding Explanation registration remains compatible.
- The visible Administrator navigation reaches `AI Model Governance` at
  `/administration/ai-models`.
- Loading, error, empty and populated states are explicit and never use local
  fallback or synthetic data.
- Loading the endpoint or page performs no registry mutation or provider call.
- API responses contain no credentials, secrets, prompts, provider responses,
  sessions or internal configuration objects.

## Non-Goals

No provider activation, policy editing, credential management, arbitrary model
selection, model execution, fallback, AI hypothesis generation, benchmarking,
comparison UI, live Anthropic/Google/local calls or TASK-0119.

## Implemented Architecture

- `AIModelGovernanceQueryService` projects the immutable TASK-0117 registry and
  canonical provider/capability enums without selecting or executing a model.
- Adapter implementation availability and current server-side execution
  availability are explicit bindings, separate from registration, enabled
  status and capability authorization.
- `GET /api/ai-model-governance` is input-free and read-only. Its typed response
  contains governance metadata only.
- The visible Administrator navigation item `AI Models` opens the live
  `AI Model Governance` view at `/administration/ai-models`.
- Anthropic, Google and local OpenAI-compatible providers are shown truthfully as
  governance foundation only while no canonical model identity is registered.
