## Implementierung

### Produktiver NVD Adapter

`NvdThreatIntelligenceReader` implementiert den bestehenden `ThreatIntelligenceReader`-Port und verwendet die offizielle NVD CVE API 2.0:

`GET https://services.nvd.nist.gov/rest/json/cves/2.0?cveIds={CVE-ID}`

Der Adapter folgt dem vorhandenen `requests.Session`-Infrastrukturpattern. `NVD_API_KEY` ist optional und wird, falls vorhanden, ausschließlich als Environment Reference im offiziellen `apiKey`-Header verwendet. Der öffentliche NVD-Zugriff benötigt keinen künstlichen Credential-Zwang. `NVD_TIMEOUT_SECONDS` ist konfigurierbar und standardmäßig `15`.

Offizielle Grundlage: NVD Vulnerability API und NVD Start Here unter `https://nvd.nist.gov/developers/vulnerabilities` beziehungsweise `https://nvd.nist.gov/developers/start-here`.

### NVD → Contract 1.0 Mapping

* angefragte und zurückgelieferte CVE-ID müssen exakt übereinstimmen
* englische NVD-Beschreibung sowie `published` und `lastModified` werden in `NvdIntelligence` übernommen
* ausschließlich CVSS-Metriken mit Source `nvd@nist.gov` werden gemappt
* Priorität der unterstützten NVD-Metriken: CVSS 4.0, 3.1, 3.0, 2.0
* CVSS-Version, Base Score, Vector und vorhandene Severity werden in `CvssInformation` übernommen
* tatsächlicher UTC-Retrieval-Zeitpunkt wird als `observed_at` gesetzt
* NVD- und CVSS-Facts erhalten die konkrete NVD-API-URL als Source Reference
* fehlende NVD-CVSS-Metrik wird `no_data`, niemals Score `0`
* EPSS, CISA KEV und Exploitation Evidence bleiben `not_evaluated` mit `value=None`

NVD erzeugt keine Aussagen über known/active exploitation, EPSS, KEV, Actors, Campaigns, Malware, IOCs, Environment Relevance, Risk, Priority oder Decision.

### Fehler-/Availability-Semantik

* syntaktisch ungültige CVE: HTTP `422`, Reader wird nicht aufgerufen
* gültige, nicht gefundene CVE (`totalResults=0`): Application Not Found → HTTP `404`
* NVD Transport-/HTTP-Fehler: Source Unavailable → HTTP `503`
* NVD Timeout: HTTP `504`
* ungültiges JSON oder unerwartetes Schema/CVE-Mismatch: Invalid Response → HTTP `502`
* keine Fehlerklasse wird in `no_data`, `false` oder Fake-/Fallback-Intelligence umgedeutet

### Application-/API-Verdrahtung

Die bestehende FastAPI Dependency erzeugt nun `NvdThreatIntelligenceReader.from_settings()` und übergibt ihn an `ThreatIntelligenceQueryService`. Providerlogik verbleibt vollständig in `infrastructure`; der freigegebene Endpoint und die Contract-1.0-DTOs bleiben unverändert.
