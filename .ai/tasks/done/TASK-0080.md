## Scope

Implement a minimal read-only Finding→Incident query boundary over the
canonical `SecurityIncidentContext 1.0` relationships and expose the result in
the existing SOC Analyst Dashboard `Investigation Context` area.  A returned
incident reference must provide a dynamic entry to the existing Incident
Command Center route.

No incident creation, persistence changes, lifecycle commands, mock data,
hardcoded incident IDs, or unrelated dashboard areas are in scope.

## Browser-Acceptance-Remediation

Die erste Live-Acceptance meldete `Incident context could not be loaded`.
Der reproduzierte Backend-Prozess hatte kein `INCIDENT_CONTEXT_PATH` gesetzt;
die Runtime-Datei war vorhanden, aber für `FileIncidentContextRepository`
nicht erreichbar. Der Endpoint war zu diesem Zeitpunkt nicht erreichbar bzw.
lieferte ohne Konfiguration keinen Incident Context.

Die minimale Remediation war ausschließlich die lokale, bereits vorgesehene
Environment-Konfiguration:

`INCIDENT_CONTEXT_PATH=runtime/incident-contexts.json`

in der ignorierten lokalen `.env`-Datei. Keine Produktlogik wurde geändert.
Mit dieser Konfiguration liefert der reale Request:

`GET /api/findings/6d3167e9-002c-4b76-a5a7-ce47f81b78b1/incidents`

HTTP `200` mit Incident `incident-task0077-distcc-live`, Relationship Role
`investigation_candidate` und Lifecycle `investigating`. Eine unbekannte
Finding-ID liefert weiterhin HTTP `200` mit `[]`.

Die erneute Browser-/Product-Owner-Acceptance steht noch aus.

`GET /api/findings`-Feed aus dem DVWA-Report
`C:\Users\sinii\Desktop\report-f70ee8ed-8e00-417b-90f2-0e451f307fc3.xml`
mit fünf Findings stammte. Dieser Report enthält das DistCC-Finding nicht.

Der bereits vorhandene reale Metasploitable2-Report
`C:\Users\sinii\Desktop\xxx.xml` enthält 69 Findings einschließlich
`6d3167e9-002c-4b76-a5a7-ce47f81b78b1`.

Die lokale ignorierte `.env` wurde daher ausschließlich um folgende
Konfiguration ergänzt:

`GREENBONE_REPORT_PATH=C:\Users\sinii\Desktop\xxx.xml`

der Finding→Incident-Request weiterhin die persistierte Beziehung. Keine
Produktdatei und keine Incident-Persistenz wurde verändert.
