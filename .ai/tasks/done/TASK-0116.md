## Objective

Allow an authenticated and explicitly authorized human Local Operator to create
a canonical Hunt Hypothesis draft through the Threat Hunter UI. Architect
Rework #1 adds the approved backend-owned bootstrap and in-memory browser
session without delivering the long-lived credential to React.

## Implemented Backend Boundary

- `POST /api/hunt-hypotheses` accepts only human-authored title, statement,
  rationale and canonical target/threat pointers.
- `HuntHypothesisCreationService` reuses the TASK-0115 authority boundary.
- The server assigns UUIDv4 identity, authenticated principal ID, trusted UTC
  timestamp, `draft` status and canonical contract version.
- Reference resolution remains separate; canonical unresolved pointers are
  preserved without rewriting or pre-validation against external sources.
- `AuthorizationDecision` is retained in the immutable creation result as the
  audit-ready actor, operation, timestamp and outcome projection. No suitable
  existing durable product audit store was found, so no parallel audit
  persistence framework was invented.

## Persistence Safety

The configured JSON repository uses a repository-scoped in-process mutex plus
an OS-managed inter-process lock (`msvcrt.locking` on Windows, `flock` on
POSIX). While locked it strictly reloads and validates the complete repository,
rejects duplicate identities, writes the full canonical document to a
same-directory temporary file, flushes and fsyncs it, atomically replaces the
repository, verifies the persisted record and releases both locks in `finally`.
Malformed repositories and write/replace failures remain fail-closed.

## API Semantics

- 201: exact persisted canonical hypothesis;
- 401: missing or invalid Local Operator authentication;
- 403: authenticated principal lacks exact creation permission;
- 409: generated identity conflict;
- 422: invalid request or canonical structure;
- 503: repository configuration, locking or safe persistence unavailable;
- 500: repository integrity/data failure.

Responses do not expose filesystem paths, credentials or internal exception
details. Caller-supplied authoritative metadata is rejected as an extra field.

## Architect Rework #1

FastAPI now owns a script-free, loopback/Host-restricted credential bootstrap.
Successful TASK-0115 authentication rotates a single opaque, server-side
session and sets only its random identifier in an HttpOnly, SameSite=Strict,
host-only cookie. The in-memory store retains hashed session/CSRF identities,
trusted principal binding, configured origin and absolute expiry. Restart,
logout, expiry and re-bootstrap invalidate sessions.

The session API returns only the re-derived safe principal projection, expiry
and an independent CSRF token. Session-authenticated mutations require the
exact configured Origin and constant-time CSRF validation before creation.
Credentialed CORS remains restricted to the explicit configured origin.

The Hypotheses page detects the session, otherwise links directly to the
backend bootstrap, and exposes a manual canonical creation dialog only when
authenticated. React never receives or stores `LOCAL_OPERATOR_TOKEN` or the
HttpOnly session identifier. Successful creation refreshes the canonical list;
failure remains visible without fabricating success.
