## Problem

PredatorAI correctly refuses deterministic risk assessment when any required
`RiskAssessmentInput` is not authoritative. The supported Product path supplies
canonical asset and business context, but does not supply authoritative exposure
or effective detection coverage. Existing threat-intelligence and MITRE-related
evidence is not promoted into the compatibility risk inputs. A real Greenbone
finding therefore cannot reach `RiskAssessmentStatus.ASSESSED` through supported
Product paths.

## Product Outcome

Prove one non-mock vertical chain:

```text
Greenbone Finding
-> Canonical Asset
-> Existing Business Context
-> Authoritative Exposure Context
-> Authoritative Detection Coverage Context
-> Deterministic Threat-Intelligence Promotion
-> Governed MITRE Context
-> all RiskAssessmentInput values AUTHORITATIVE
-> RiskReadinessService ASSESSED
-> unchanged deterministic score
-> supported API/UI result with exact provenance
```

Also prove the mandatory negative chain: when one required detection observation
is missing, expired, invalid, revoked, stale or conflicted, readiness returns
`INSUFFICIENT_CONTEXT`, no score is produced, and the exact requirement is visible
through the same Product API/UI path.

## Authoritative Architecture Decisions

1. Exposure means current external/untrusted-network reachability relevant to the
   affected asset/service/finding. Authentication-protected external reachability
   still projects `true`.
2. Detection `true` requires an applicable healthy sensor/source, current relevant
   telemetry, an applicable rule, enabled rule, and operational alert path.
3. Unknown, partial, stale or conflicted coverage cannot project `true`.
4. Use a shared immutable observation metadata envelope with strongly typed
   exposure, detection and MITRE payloads; no generic key/value context bag.
5. Observation history is append-oriented. Supersession and revocation are new
   immutable records; source observations are never silently overwritten.
6. Freshness is configured per source/policy. Domain logic contains no universal
   TTL.
7. `STALE` and `CONFLICTED` block readiness.
8. The initial producers are vendor-neutral structured imports. Greenbone scanner
   presence and legacy booleans are not exposure/detection authority.
9. MITRE authority is a governed, versioned structured mapping import. AI cannot
   assign authoritative MITRE context.
10. Operational fact authority is permission- and scope-based. Product Owner and
    system-administrator authority do not confer operational truth authority.
11. The initial runtime is single-organization, while every observation carries a
    mandatory organization boundary.
12. File/embedded persistence is behind a repository abstraction replaceable by a
    later store.
13. The existing deterministic risk-score formula is unchanged.
14. Manual attestation is representable as a future typed producer and must expire,
    but its API/UI and dual-approval workflow are deferred.

## Exact Domain and Application Contract

Implement immutable, strictly validated contracts for:

- shared `ContextObservation` metadata: deterministic identity/digest,
  organization, typed context discriminator, subject, exact scope, source,
  provenance, evidence references, timezone-aware observation/ingestion/expiry,
  authority policy, schema version, and optional supersession/revocation;
- typed exposure observations and current projection states including external,
  internal/local, unknown, stale and conflicted;
- typed detection observations retaining sensor applicability/health, telemetry,
  analytic identity/version/applicability/enabled state, alert-path state, and
  overall projection;
- typed governed MITRE technique/tactic mappings;
- repository, strict structured-import reader, source/authority validator,
  freshness evaluator, supersession/revocation evaluator, conflict projector,
  exposure projector, detection projector, threat-intelligence promoter, MITRE
  promoter, and compatibility risk-input promoter.

Exposure compatibility projection is `true` for direct, transitive, or
authentication-protected external reachability. An authoritative `false` requires
an explicit current negative evaluation within the exact service/path scope.
Unknown, stale and conflicted observations emit no boolean.

Detection compatibility projection is `true` only when every approved condition
is positively established for the exact asset/finding/technique scope. A completed
negative evaluation may produce authoritative `false`; missing evidence remains
non-authoritative.

Threat-intelligence `true` requires same-finding canonical applicability and the
existing complete correlation evidence with exact finding, CVE and source-fact
references. Lookup success alone is insufficient. MITRE promotion requires an
exact current governed mapping; CVE presence, CVSS effects, title text and AI are
not mapping authority.

## API and UI Contract

Extend only `GET /api/findings/{finding_id}/risk-context`. Preserve all existing
fields and add typed context projections exposing value/status, observation and
evidence IDs, source/authority reference, observed/ingested/valid-until times,
derivation identity, missing requirements, and conflict references.

Extend only the existing SOC Finding risk-context section. It must show assessed
or blocked state, all required inputs, exact missing/stale/conflicted reasons,
source/provenance/freshness, and the unchanged score when assessed. Informational
guidance may say configure/import, refresh, or review conflict; no write workflow
may be implied.

## Persistence Contract

Use a configured directory and a `ContextObservationRepository` abstraction.
Persist one immutable record per exposure observation, detection observation and
MITRE mapping. Exclusive creation and read-back digest verification are required.
Exact repeats are idempotent; the same identity with changed content is rejected.
Current projections may be computed on read for this slice. Audit accepted,
rejected, idempotent, stale, conflicted, superseded, revoked and promoted events
without secrets.

## Security, Temporal, Conflict and Provenance Acceptance

Reject unknown sources/organizations, untyped payloads, canonical identity or
scope mismatches, missing evidence, naive/invalid timestamps, unsupported schemas,
invalid digests, changed duplicate identities, replayed revocations, invalid or
cross-subject supersession, Greenbone defaults as authority, AI context, and
administrator/Product Owner identity as fact authority. Prove sensor-only,
telemetry-only, rule-only, disabled-rule and unavailable-alert-path cases cannot
produce detection `true`.

Source-specific policies determine freshness. Expired observations become `STALE`
and remain historical. Current contradictory same-scope observations become
`CONFLICTED`; no source is silently selected and no boolean is projected. Different
services/scopes/windows do not create false conflicts.

Every promoted input retains organization, subject/scope, observation/evidence
IDs, source and authority references, all timestamps, schema/digest, derivation,
and supersession/revocation/conflict state.
